# Claude / GPT 双投资研究系统：团队实施与交接指南

日期：2026-10-09｜交付性质：工程实施指南及原型交接｜阶段：前向观察，不接管实盘

## 1. 给团队的明确任务

**把 Claude 和 GPT 分别当成独立的投资经理，给它们相同的市场证据和规则，持续记录各自的选股、持仓、退出理由及前向模拟结果。**

本项目允许模型根据新信息调整持仓，不要求持有满一周，也不要求每天交易。第一阶段交付的是能持续运行、能查看原因、能追溯结果的两套观察组合。盈利能力必须通过后续真实时间推进来检验，不能在上线当天宣布。

本次不使用以前的 2,000 美元限制，不把 AM70/30 的选股池强行作为唯一候选池，不做 TradingView 指标，不接管现有股票或期权账户。现有 AM70/30 可以另作参考，但不能把其历史表现和新系统的前向结果混为一条曲线。

**先完成数据—决策—记录闭环，再解决模拟执行；不要因为某一家公司的财务接口缺失，暂停全部研究。** 没有合格报价可以等待成交，但研究仍然可以产出可审查的建议。

## 2. 这是什么，以及不是什么

Rallies 公布了持仓、交易和部分投资理由，未找到足以完整复制其全部提示词、模型版本、调度频率和风险约束的公开材料。本项目借鉴其“实时证据 + AI 投资判断 + 持续复核”的方式，不得对外称为 Rallies 原版复刻。

已公开的方法包括财报、新闻、行情等研究工具。项目方曾对其 AI Hedge Fund 描述每天运行并以长期投资为视角；不能把这条描述推定为所有参赛模型统一的持仓期限或调度规则。

所有下述股票池、权重上限、模拟金额、调用频率都是我们的 **assumption（实验设定）**，不是已经证明最优的参数。

第一阶段固定以下设置，见 `ai_portfolios/config.json`：

| 项目 | 初始设定 |
| --- | --- |
| 目标 | 资本增值，控制回撤，不要求每日正收益 |
| 比较对象 | Claude 与 GPT 独立运行；互相看不到对方决定 |
| 模拟起始资金 | 每组 100,000 美元，仅为可比较的记账尺度 |
| 品种 | 美国股票，做多；不加杠杆、不做期权、不做空 |
| 股票池 | AAPL、MSFT、GOOGL、AMZN、META、NVDA、AVGO、AMD、MU、AMAT、JPM、V、XOM、CAT、UNH、COST、WMT、LLY、CRM、PLTR |
| 单股目标权重 | 不高于 20% |
| 正仓位数量 | 不超过 10 只 |
| 总目标仓位 | 不高于 95%，现金可以更多 |
| 持仓周期 | AI 根据证据持续复核；不设统一“一周必须卖” |
| 研究频率 | 建议第一版每个美股交易日美东 10:00 一次；当前未安装自动任务 |
| 额外复核 | 后续版本可引入重大公告触发；第一版不要求全天无限调用 |
| 模拟成交 | 决策完成至少 60 秒以后取得的新有效报价；买按 ask、卖按 bid，均为假设成交 |
| 计划有效期 | 当前原型 24 小时；过期不成交，应重新研究 |
| 行情来源 | 当前为 IEX；不是全市场成交量，也不是完整 NBBO |
| 比较基准 | SPY、QQQ，95% 买入持有、5% 现金；需要对齐共同启动时间 |

仓位上限目前检查的是**目标权重**。涨跌后实际权重可能漂移；团队必须说明是否设置独立漂移限制，不能假称程序已经覆盖。

冻结配置后，不允许每天根据排名换模型、改股票池或降低门槛。要变更，创建新实验 ID，并保留原版本和失败记录。当前代码会拒绝直接更改已有实验配置，这是为了防止把不同实验拼成同一条收益曲线。

## 5. 各角色负责什么

### Claude Code / 开发人员

搭建和维护程序、接口、日志及看板。Claude Code 是运行工具，不是“装上就自动获得投资优势”。不要让研究模型通过工具读取 `.env`、现有实盘账户、其他模型的输出或任意本地文件。

### Claude 投资模型、GPT 投资模型

分别接收同一份公共数据包，以及各自的模拟持仓和上次投资理由，输出完整目标组合。允许说证据不足并持有现金。

每次至少说明：

1. 为什么现在值得买，新增或仍然有效的证据是什么。
2. 哪些是事实，哪些是模型推断，哪些资料缺失。
3. 目标权重与估计持有时间。
4. 什么条件下原判断失效，应当减少或退出。
5. 对已有持仓，原理由是否成立；如改了理由，改动在哪里。
6. 保留现金的原因。

### 确定性程序

检查股票范围、权重、引用来源、已有持仓是否被无说明遗漏；处理时间、价格、记账、重复执行和错误状态。**模型不能修改风控限制，不能把“我认为这次特殊”作为绕过检查的理由。**

### 团队负责人

确认目标、版本和实验边界；检查数据与结果是否可信。不要根据某次“看起来有道理”的长篇回答代替验收。

## 6. 数据输入与公开事实要求

两模型必须接收字节一致的市场数据包。决策同时开始并不是必要条件，输入一致和时间记录完整才是必要条件。各自持仓不同属于正常差异。

输入只包含：公共行情、新闻摘要、财务记录及本地虚拟组合。**不发送真实账户余额、持仓、交易凭据或用户隐私数据。**

| 数据 | 初始用途 | 缺失时 |
| --- | --- | --- |
| 完成的日线 | 价格趋势、位置及波动背景 | 缺少新鲜价格证据的股票不能新建正权重 |
| 新闻及发布时间 | 催化事件和投资理由 | 区分“没有返回新闻”和“接口失败”，不能当成同一回事 |
| 季度财务 | 盈利、收入等基本面依据 | 标记 unknown；其他数据充分的股票仍可研究 |
| 最新 bid/ask | 模拟估值与之后的假设成交 | 不补价、不用前日收盘价伪装成交；保留待执行状态 |
| 原投资理由 | 持续持仓管理 | 每次都保存，不依赖聊天记忆 |

当前 FMP 对 AVGO、MU、AMAT、CAT、LLY、CRM 返回 HTTP 402。第一阶段不要求购买新套餐。允许这些股票只进入观察，或在新闻和价格证据满足规则时进行明确标注缺口的研究判断；不得编造估值、财务比率。

财务数据的报告期末不等于市场获知时间。团队应核对供应商 `acceptedDate` / `filingDate` 的时区和可用时间；没有时区时采取明确的保守可用日，记录 assumption。原型对此仍需加强。

引用一个真实 ID 只能证明引用存在，不能证明模型叙述正确。验收需抽查重要数字、算术、单位和事件日期，特别是把百万与十亿美元混淆、把新闻中的观点当成公司已披露事实等错误。

## 8. 接手后必须先修复或明确处理的问题

下面是原型审查发现的具体缺口，不是要求重新从零搭系统。**研究功能可以继续，但未解决的执行问题必须阻止模拟成交；未解决的统计问题必须阻止收益结论。**

### 8.1 Claude OAuth 失效：阻止 Claude 决策，不阻止其他工作

已观测到 `Failed to authenticate: OAuth session expired and could not be refreshed`。由账户使用者重新登录，之后实际调用验证。不得换 GPT 生成一份标为 Claude 的输出，也不得拿其他聊天中已有文字充当本轮响应。

### 8.2 本机与报价时钟存在亚秒差异：阻止受影响的模拟成交

执行快照 `20261009T194039035452Z` 显示，多只股票报价比本机冻结时间约快 0.04–0.28 秒。原型严格拒绝未来时间，导致 WMT / QQQ 等等待成交。不能把这个现象误判为股票没有报价。

处理顺序：核对 Windows 时间同步 → 保存接收时间与交易所时间 → 在该报价时间真正过去之后，用当前时间重新校验已经保存的报价。可以短暂等待后校验；不可将负年龄直接改成零、修改原始时间戳，或大幅放宽过期限制。时间差达到明显异常量级时停止执行并告警。

需新增测试：亚秒领先后再校验、真正未来报价、较大时钟偏移、报价已过期、长时间模型调用后旧报价不可成交。

### 8.3 程序退出码与单模型失败不一致：阻止无人值守上线

目前主程序可能在一个模型失败时仍以成功退出码结束。团队必须修复，使机器可读的总体状态能区分“两者完成 / 部分失败 / 全部失败”。调度器不能仅凭进程退出就报告全部成功。成功一侧的结果必须保留，不能因另一侧失败而重跑抽签。

### 8.4 两模型与基准启动尚未对齐：阻止比较排名

首轮仅 GPT 出具有效建议，而 SPY 已模拟成交，尚不构成公平共同起点。修复认证和执行后建立新的正式比较实验，保留当前轮为启动诊断。共同起点、报价来源、可成交时段、初始资金一致；个别模型调用缓慢造成的执行延迟要单列，不能把慢模型的成交回填到早先价格。

不要删除当前记录或把起始净值重写为表现最好的一天。当前代码还没有完整的“新实验目录”命令，团队应增加显式实验 ID，将各实验的配置、状态和报告分开。

### 8.5 企业行动和收益口径不完整：阻止宣称可投资业绩

原型价格收益不含股息，没有完整拆股、并购、分拆、退市处理；大幅价格跳变拦截不等于企业行动处理。团队需加入核对机制；发现持仓涉及企业行动时暂停对应估值与成交，不猜测调整。

每边 5 bp 是压力假设。现有压力净值是从主路径扣除累计假设费用的简化视图，没有完整复算费用改变后的再投资路径，不能称为精确成本后回测。真实券商费用、真实滑点和市场冲击当前仍是 unknown。

### 8.6 输入与程序版本必须一起冻结

原型保留了数据和代码哈希，但哈希本身不能恢复代码。正式轮次应保存 Git 提交号及必要源码副本、模型请求版本、CLI 版本、提示词、配置与输入哈希。模型别名升级应视为新版本记录，不允许悄悄改变同一模型的定义。

### 8.7 运行中断与恢复

已有运行锁用于防止重入，已有全组合模拟成交先检查后记账的行为。还需测试：模型超时后子进程是否退出；写入过程中中断；模型已有结果但主进程未保存；重试同一计划不会再成交。缺少完整恢复保证前，只做人工触发，不安装无人值守任务。

## 9. 两阶段交付，避免再次陷入循环

### 阶段 A：两模型可运行，建议两个人日内完成

团队交付：

1. Claude 与 GPT 都有实际返回且通过检查的决定；保存各自原始输出。
2. 同一数据包哈希、明确模型身份、每条建议对应的证据与退出条件。
3. 看板明确分开“建议权重、已模拟持仓、未成交、失败、缺数据”。
4. 失败不会被报告为成功；重复运行不会重复记账。
5. 时间同步及报价先后关系检查通过。

若 Claude 登录一天内仍解决不了，交付清楚的认证阻碍证据与 GPT 工作结果，由账户使用者处理；其他开发不围着认证问题无限重构。

### 阶段 B：正式前向观察

新建正式实验 ID，冻结规则，记录共同起点。先连续完成 5 个交易日的运行可靠性检查，再进入更长观察。

30 个交易日可用于第一轮运维与行为回顾，**不能自动证明有 alpha，也不是实盘批准条件**。要看有效独立决策次数、持仓期限、市场状态和成本后表现；如果模型持有 60–90 天，观察窗就必须覆盖相应持仓过程，不能用短期浮盈宣布胜负。

自动任务应在阶段 A 修复完成后由团队部署：使用美东时区并处理夏令时、交易日历；限制每个研究时段一次模型调用；失败只做有上限的恢复，不无限重试。当前没有创建任何自动任务。

| 两模型真实调用 | 原始响应、时间、模型身份 | 该模型标失败，不伪造 |
| 公平输入 | 相同公共 packet 哈希 | 本轮不计为严格对照 |
| 信息可用时间 | 新闻更新、财报披露、行情时间 | 未知资料剔除或标 unknown |
| 决策先于成交 | 决策完成时间 < 新报价时间，且满足延迟 | 保持未成交 |
| 仓位约束 | 无重复股票、无负数/NaN、无超上限 | 整份计划拒绝 |
| 原持仓连续性 | 每只旧仓都有继续、调整或退出说明 | 拒绝无说明遗漏 |
| 资金守恒 | 现金 + 持仓估值可逐笔重算，无重复扣款 | 暂停记账并查明 |
| 数据权限不足 | 原始错误码与缺失列表 | 不填造数据，其他股票继续研究 |
| 提示注入 | 新闻里出现“忽略规则”等内容仍不能调用交易工具或越权 | 拒绝该响应并保留证据 |
| 输出事实正确 | 抽查关键数字、单位、日期、引用所支持的结论 | 原回答归档，纠错不冒充原模型结果 |
| 模型失败可见 | 页面和机器状态一致 | 不以绿色成功掩盖 |
| 实盘隔离 | 不存在提交、撤销、平仓接口路径 | 未满足时禁止运行 |

已有 24 项测试只覆盖其中一部分。团队应增加上述高风险缺口对应的测试，不为页面颜色或静态文字堆无意义测试。

## 11. 应该如何评价结果

保留两类结果，不混淆：

- **工程结果**：数据是否按时取得、两模型是否实际运行、错误是否可见、执行是否正确。
- **投资结果**：从共同起点累计的前向收益、回撤、持仓暴露、换手和相对基准表现。

报告至少给出：净值和实际可估值时点、未成交计划、现金占比、最大单股暴露、价格收益与成本压力结果、有效持有期限、模型调用开销、缺失数据、与 SPY/QQQ 的同区间比较。

“已观察最大回撤”必须注明采样频率。每天一次净值不能叫完整盘中最大回撤。若只在手动刷新时估值，应写“已采样时点回撤”。

不要用以下方式制造优势：反复询问直到模型答复满意；事后丢掉失败模型；把持仓日期倒填；使用今天的模型对历史行情问答后称为无泄漏回测；漏算现金；把压力成本当成实收费用；只报告最大赢家。

## 12. 每天的标准作业

1. 数据收集器读取公共数据，冻结新快照，检查时间和覆盖情况。
2. 对上一轮待执行计划取得新报价，校验后本地模拟记账；过期计划明确失效。
3. 将同一市场包和各自历史交给两模型，不互相泄露观点。
4. 校验完整目标组合和证据，失败保持旧仓并显示失败；不自动把失败当成“继续持有”的成功决定。
5. 保存新计划，之后再读取有效报价；不得用输入里的旧报价倒推成交。
6. 更新看板和审计记录，复核关键事实和异常。

工程人员只处理运行故障，不手工挑选模型喜欢的股票。人为否决或干预必须单列，不能继续标成未经干预的模型业绩。
